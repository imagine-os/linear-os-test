### PAP-281 — orchestrator: Linear polling, atomic claim and state transitions

* The claim half of the orchestrator: `claimNext()` with the `updatedAt`
  guard and the pre-claim Deferred/umbrella re-check, `release()`,
  `recoverClaims()` (restart recovery), `toInReview` / `retry` / `escalate`,
  and `linearComment()` with the PAP-92 footer and `(issue_id, sha256(body))`
  dedupe.
* `src/loop.ts` runs the cycle and exposes `registerPass(name, fn)` so
  PAP-691's promotion pass and PAP-703's SLA evaluator plug in without
  editing it; `launchSession` is a port with a `DryRunLauncher` default
  (PAP-282 supplies the real one). `wake()` is there for PAP-97.
* Paths: `src/config.ts`, `src/db/{index,schema}.ts`, `src/events.ts`,
  `src/http.ts`, `src/validator.ts`, `src/linear/{issues,filters,claim,
  transitions,comment}.ts`, `src/session/launcher.ts`,
  `src/cli/{loop,status}.ts`, `orchestrator.config.yaml`,
  `docs/pm/orchestrator.md`, `tests/` (+62 tests, fixture
  `tests/fixtures/promotion-graph.json`).
* Deviations: the `updatedAt` guard is taken before the Linear write, not
  after (a post-write comparison can never match); `node:sqlite` instead of
  `better-sqlite3` (no native build, no root `allowBuilds` change, same
  driver PAP-93 chose). Both are argued in `docs/pm/orchestrator.md`.
* No ADR: the orchestrator's shape is settled by PAP-96's spec.
* Review fix (Sentinel): `isDeferred()` only fires on a deferral *statement*
  under Goal (a sentence starting `Deferred`, or `deferred to v0.<n>` /
  `deferred until`), scoped to the Goal section; the earlier `\bdeferred\b`
  check skipped PAP-695 and PAP-701 on live data. The not-claimable comment
  now says whether the label or the note triggered it. `src/linear/filters.ts`,
  `src/linear/claim.ts`, `tests/filters.test.ts`.
